Review triggering is stateless by design (replaces an earlier state-file counter approach): total turns are computed each round from `sessionManager.getBranch()` (count user+assistant messages ÷ 2) and trigger at integer multiples of reviewTurns — no persisted counter, so reload/resume can't reset it, and compaction entries (not counted as messages) stay in the branch so pre-compaction turns still count. Memory flush extraction runs only on `session_shutdown` with `reason === "quit"` (pi awaits this handler; cap at ~30s via LLM_TIMEOUT_MS so quit isn't blocked); reload/new/resume/fork do not trigger. Possible overlap with periodic extraction (flush shortly after a periodic run) is mitigated by dedup plus feeding only the branch tail (~20 entries) to the flush prompt; skip flush if <4 messages.
